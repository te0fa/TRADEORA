## Section 5 — Architecture Freeze Rules

From Architecture Freeze v1.2 FINAL, the following rules are permanently in effect:

### Rule 1: Implementation Lock
All 91 documents in this manifest constitute the implementation baseline.
Engineers MUST implement what is documented. Undocumented patterns are not permitted.

### Rule 2: Change Control
Architecture changes are permitted ONLY through:
1. **Critical Security Issue** — immediate ECR, Architecture Council emergency session
2. **Critical Architectural Defect** — documented ECR, Architecture Council approval
3. **Approved Enterprise Change Request (ECR)** — full board approval process

### Rule 3: Future Evolution
All ideas for improvement, new features, or enhancements that do not qualify as ECRs
MUST be recorded in the Future Evolution Backlog (in ARCHITECTURE_CHANGE_LOG.md).
They are NOT permitted during Phase 8 implementation.

### Rule 4: Compliance Non-Negotiables
The following decisions are permanently frozen and cannot be changed by any ECR:
- Decimal arithmetic for all financial calculations (Article 17)
- Arabic language for all user-facing AI output
- FRA disclaimer on every recommendation
- WORM audit trail for every recommendation
- PDPL cryptographic erasure pattern (SAGA-004)
- Human-in-the-Loop for all AI advisory output (Article 6)
